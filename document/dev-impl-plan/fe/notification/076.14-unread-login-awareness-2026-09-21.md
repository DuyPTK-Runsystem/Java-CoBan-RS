# Plan 076.14 FE — Notification unread awareness after login

## 1. Scope and source

- Application-document version: **v3**.
- Scope: authenticated FE shell awareness for unread v3 notifications.
- Source contract: `document/application-doc/v3/modules/03-NotificationAndAudience.md`.
- Related implementation: Plan 076 targeted notification UI.

## 2. Approved behavior

After a successful login, the authenticated shell loads the current user's unread v3
notification total through the existing typed inbox endpoint. The `Thông báo` navigation
item displays a visible count badge when the total is greater than zero. A count-loading
failure is non-blocking and must not prevent the workspace from rendering.

The change does not add push, polling, email fallback, a new backend endpoint, or a
cross-scope count. The backend remains authoritative for recipient scope and read state.

## 3. Implementation boundary

Production code is limited to the existing notification API service, authenticated shell,
and shared navigation presentation. Test files are maintained by a separate QA worker and
are not changed by the development worker.

## 4. Acceptance and validation

- authenticated shell requests unread inbox metadata with `unreadOnly=true`;
- the navigation badge reflects `meta.totalItems` and is hidden for zero;
- API/count failures leave login/workspace usable;
- focused FE tests cover serialization, badge rendering, and failure handling;
- lint/build/full FE and browser/live evidence remain separate gates.
