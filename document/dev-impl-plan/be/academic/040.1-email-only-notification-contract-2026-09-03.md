# Developer Plan 040.1: Email-only Notification Contract Amendment

- **Trạng thái**: `Approved` — user đã phê duyệt bằng tin nhắn qua agent ngày `2026-09-03`.
- **Plan liên quan**: `040 - Semester Completeness Notification (CR-SEM-001)`.
- **Phạm vi**: Backend notification domain, persistence contract, service, tests và documentation.

## 1. Mục tiêu

Chuẩn hóa notification contract thành email-only. Hệ thống chỉ ghi nhận `SENT` khi lệnh gửi qua `JavaMailSender` trả về thành công; không cam kết hoặc kiểm tra việc người nhận đã nhận email.

## 2. In-scope

- Xóa giá trị `IN_APP` khỏi `NotificationChannel`.
- Tạo Flyway migration kế tiếp để ràng buộc `notification_channel` chỉ nhận `EMAIL`.
- Migration phải không xóa dữ liệu. Nếu dữ liệu production còn `IN_APP`, migration phải fail an toàn để xử lý riêng, không tự chuyển đổi hoặc xóa bản ghi.
- Giữ `checkpointCode` và `notification_channel` trong persistence/idempotency nội bộ khi cần; không biến chúng thành UI concern.
- Cập nhật entity, DTO mapping, repository/service và tests để chỉ dùng `EMAIL`.
- Kiểm tra các API notification hiện có; không tạo endpoint mới.
- Cập nhật tài liệu Plan 040/Dev Note liên quan và tạo Dev Note 040.1.

## 3. Out-of-scope

- Không sửa FE Plan 059/060.
- Không thay đổi URL, method hoặc quyền của ba API notification hiện có.
- Không lưu password mail, token hoặc credential trong source, log, Developer Plan hay Dev Note.
- Không kiểm tra delivery/read receipt của người nhận.

## 4. Phương án migration an toàn

Tạo migration additive sau `V18` để thêm constraint `EMAIL` trước, rồi mới bỏ constraint legacy. Migration không cập nhật/xóa các dòng hiện có. Nếu còn dòng `IN_APP`, bước thêm constraint mới thất bại trước khi constraint cũ bị bỏ; preflight vẫn cần dùng truy vấn kiểm tra dữ liệu trước production rollout.

## 5. Validation dự kiến

- Unit/focused tests cho dispatch thành công, mail failure và idempotency.
- Flyway migration test xác nhận constraint chỉ cho phép `EMAIL`.
- `test`, `checkstyleMain`, `pmdMain`, `build` từ `BE/BaiTap-RS`.
- Ghi `PASS`, `FAIL` hoặc `NOT RUN` theo lệnh thực tế.
