## 1. Mục tiêu

Sửa lỗi tạo/xác nhận phiên xếp lớp bị rollback khi MySQL từ chối
`audit_log.after_data` vì service đang ghi chuỗi dạng `classes=4` hoặc
`results=40` vào cột `JSON`.

Kết quả mong muốn:

- audit tạo phiên lưu JSON hợp lệ, có số lớp đích;
- audit xác nhận phiên lưu JSON hợp lệ, có số kết quả;
- thao tác hủy vẫn được phép ghi `after_data = null`;
- không đổi contract API, schema, seed hoặc logic năm học/xếp lớp.

## 2. Requirement và constraint

- `NFR-V3-002`: mutation quan trọng phải có audit phù hợp.
- Plan 074 yêu cầu create/confirm có audit và confirm giữ transaction atomic.
- Hai cột `audit_log.before_data` và `audit_log.after_data` có kiểu MySQL `JSON`;
  mọi giá trị khác `null` phải là JSON hợp lệ.
- Không nuốt lỗi serialize và không ghi fallback không hợp lệ.

## 3. Kiến trúc và nguyên nhân hiện tại

Luồng lỗi hiện tại:

```text
PlacementService.create/confirm
  -> PlacementConfirmationSupport.audit(..., "classes=..." / "results=...")
  -> AuditLog.afterData
  -> MySQL JSON validation
  -> DataIntegrityViolationException
  -> rollback + HTTP 409 chung
```

`PlacementConfirmationSupport` đang nhận chuỗi đã định dạng sẵn, trong khi entity
`AuditLog` ánh xạ `after_data` sang cột `JSON`. Chuỗi `key=value` không phải JSON.

## 4. Phương án triển khai

1. Đổi boundary `PlacementConfirmationSupport.audit` để nhận dữ liệu có cấu trúc
   và serialize bằng Jackson `ObjectMapper` trước khi tạo `AuditLog`.
2. Tại `PlacementService`:
   - create truyền payload `{ "classes": <count> }`;
   - confirm truyền payload `{ "results": <count> }`;
   - cancel truyền `null` và tiếp tục lưu `after_data = null`.
3. Nếu serialize thất bại, ném lỗi ứng dụng/server rõ ràng để transaction rollback;
   không lưu chuỗi fallback và không biến lỗi kỹ thuật thành conflict dữ liệu.
4. Giữ nguyên action, entity type/id, actor, request ID và IP hiện có.

Lý do chọn phương án: JSON được tạo tại một boundary duy nhất nên caller không thể
vô tình đưa chuỗi không hợp lệ vào audit placement; không cần migration hay thay đổi
public API.

## 6. API / Database / compatibility

- API request/response/status thành công: không đổi.
- Database schema/migration: không đổi.
- Dữ liệu audit mới chuyển từ giá trị không hợp lệ sang JSON object hợp lệ.
- Không sửa hoặc backfill audit lịch sử; transaction lỗi trước đây đã rollback nên
  không có row `classes=...`/`results=...` hợp lệ để migrate trong cột JSON.

## 7. Unit test plan

- `create`: capture row audit, assert action/entity/id và parse `afterData` thành JSON;
  assert `classes` bằng số lớp đích.
- `confirm`: capture row audit, parse JSON và assert `results` bằng số kết quả.
- `cancel`: assert `afterData == null` để giữ regression behavior hiện tại.
- Serialization failure: mock/fake `ObjectMapper` ném lỗi, assert exception được
  propagate và repository audit không được gọi.
- Dependency mock: repositories, `EnrollmentService`, `ObjectMapper` khi test riêng
  support; fixture không cần MySQL hoặc thay đổi seed.
- Assertions bao phủ output audit, side effect `audits.save`, và interaction không lưu
  audit khi serialize lỗi.
- JaCoCo: đọc report cho hai class thay đổi; không tự đặt threshold mới.

## 9. Rủi ro và giảm thiểu

- Thay constructor của support làm test setup không compile: cập nhật đúng các nơi
  khởi tạo trực tiếp và dùng Spring injection cho runtime.
- Dùng map mutable/không xác định: dùng payload nhỏ, immutable và key ổn định.
- Bắt lỗi serialize không đúng semantics: không chuyển thành `409`; giữ rollback và
  biểu diễn lỗi server/application phù hợp convention hiện tại.
- Đụng worktree bẩn: Luna chỉ được ghi các file trong bảng scope và Dev Note; agent
  chính kiểm tra diff trước/sau để bảo toàn thay đổi của người dùng.

## 10. Acceptance criteria

- Create và confirm không còn thất bại vì `Invalid JSON text` tại
  `audit_log.after_data`.
- Audit create/confirm chứa JSON parse được với đúng count; cancel giữ `null`.
- Không thay đổi seed, năm học, schema hay API contract.
- Regression tests chứng minh JSON hợp lệ và failure path không ghi audit lỗi.
- Validation backend và Dev Note được hoàn tất, báo cáo đúng bằng chứng thực tế.
