# Developer Plan 035.1: Academic Office Auto-Configure Calendar on Attendance Session

## Scope and approval

- Parent plan: Plan 035, Academic Office Attendance Adjustment.
- Status: `Approved` by the user's approval for this amendment.
- Module: Backend `attendance` and the existing `calendar` service.
- This amendment applies only to `ACADEMIC_OFFICE` and `ADMIN` through
  `POST /api/v2/office/attendance-sessions`.

## Requirement

When the Academic Office/Admin presses “Mở buổi điểm danh”, a missing calendar
day or missing requested period must not expose an implementation detail to the
user. The backend must create the missing `SCHOOL_DAY` and requested
`SCHEDULED` calendar session, then create or return the attendance session with
the existing response contract.

## Decisions

- Teacher attendance flow remains strict and continues to require an already
  configured `SCHEDULED` calendar session.
- Only the requested period is auto-created; existing calendar sessions are not
  changed.
- An existing holiday, weekend/non-school day, semester mismatch, or existing
  `NO_CLASS` session is never silently overwritten and continues to return the
  normal conflict response.
- Calendar and attendance writes remain in the existing transaction. No schema
  or API response change is required.
- Calendar creation is audited using the existing calendar audit service.

## Implementation and validation

- Add an office-specific guard path that calls calendar `ensureScheduled`.
- Add calendar service/session service support for idempotent day/period creation.
- Add unit tests for auto-creation, protected non-school days, and guard routing.
- Validation results are recorded in the corresponding Dev Note after execution.
