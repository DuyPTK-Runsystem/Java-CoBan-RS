## Mục tiêu

Thông báo cho các recipient đang online sau khi notification publish transaction commit. FE nhận event `inbox-changed`, tải lại inbox/unread count qua API hiện có và reconnect khi stream đóng.

## Phạm vi

### In-scope

- Authenticated SSE endpoint `GET /api/v3/notifications/events` dùng Bearer JWT.
- In-memory registry ánh xạ user ID với SSE connections trên một backend instance.
- Chỉ gửi event `inbox-changed`, không có data payload.
- Publish event sau commit và chỉ tới recipient snapshot đã resolve.
- FE fetch-stream service có authorization header, reconnect có backoff, đồng bộ unread badge và inbox list.
- Cập nhật v3 notification module/FE API contract và Dev Note.

### Out-of-scope

- Redis/message broker, multi-instance fan-out, durable queue/outbox hoặc event replay.
- Thay thế database/inbox REST API hoặc đưa notification content vào event.
- Notification v2/email delivery changes, schema/migration, toast UI.

## Kiến trúc và luồng

Notification v3 hiện lưu receipts khi publish trong `NotificationLifecycleService`, được gọi bên trong `NotificationService.publish()` transaction. SSE endpoint lấy user ID từ `UserPrincipal`; publisher giữ emitters trong concurrent in-memory registry theo recipient user ID. Sau commit, publisher phát tên event `inbox-changed`. FE mở một authenticated fetch stream trong authenticated shell; khi nhận event, shell refresh unread count và inbox view reload nếu đang hiển thị. Nếu stream đóng, client reconnect với backoff và refresh inbox.

## Risks and tradeoffs

- In-memory SSE connections are lost on restart and do not fan out across instances. FE reconnect plus REST refresh provides eventual UI synchronization while online.
- SSE occupies one HTTP connection per active browser tab; deployment/proxy idle timeouts may close it, so client reconnect is required.
- Event is a hint, not durable delivery; offline clients discover updates on reconnect through REST refresh.

## Expected result

Online recipients see the unread badge and open inbox refresh shortly after a committed publish, without exposing notification content in the SSE frame or changing existing inbox API behavior.
