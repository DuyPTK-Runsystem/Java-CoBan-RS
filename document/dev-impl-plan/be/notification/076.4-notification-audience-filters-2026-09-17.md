# Plan 076.4 — Notification audience filters and selector UX

## Approval and scope

- Application-document version: v3.
- User approval: `approve v3` on 2026-09-17.
- Depends on Plan 076.3 audience lookup; preserve existing uncommitted work.

## Goal

- Sending by class must use a class picker; the UI must not ask for or search by a class ID.
- Sending to individuals must provide a readable filterable multi-select with role, name/search, student class and teacher class filters.

## Approved contract

Keep `GET /api/v3/notifications/audiences/individuals` and extend server-side query parameters:

```text
q, roleCode, studentClassId, teacherClassId, page, size
```

- `roleCode` filters by canonical role code (`STUDENT`, `TEACHER`, `ACADEMIC_OFFICE`, `ADMIN`).
- `q` searches the relevant display name, student/teacher code and username.
- `studentClassId` uses active student enrollment in an active academic year.
- `teacherClassId` matches the union of active homeroom and subject-teaching assignments.
- Lookup remains manager-only and `DEFAULT_SCHOOL` scoped; create/publish re-checks eligibility.
- Response may include role codes and class context needed for display, without credentials or assignment history.

## Delivery boundaries

- BE may modify notification lookup controller/service/repository/DTO and minimal projection queries.
- FE may modify notification selector/composer/types/API/tests/stories/styles.
- Do not change notification lifecycle, canonical mutation payload, v2 APIs, migrations, or router unless evidence requires an approved amendment.
- Validation is a separate follow-up agent.

## Acceptance

- No class ID input/search is rendered in the class audience UI.
- Individual UI exposes role, name/search, student-class and teacher-class filters, server-side pagination, clear-filters, multi-select chips, and loading/empty/error states.
- Canonical create payload remains `CLASS.targetReference` or `INDIVIDUAL.recipientUserIds`, never filter metadata.
- Focused BE/FE tests and configured quality gates report PASS/FAIL/NOT RUN separately.
