## 1. Phạm vi thực tế hoàn thành

- Tạo `StudentLookupService` dùng chung để resolve theo `studentId`, `studentCode`, hoặc cả hai; kiểm tra mismatch, not-found và hỗ trợ bulk lookup.
- Mở rộng Student repository/service/controller với tra cứu `GET /api/v1/students/code/{studentCode}`.
- Mở rộng Enrollment request, history endpoint và service để nhận student code cho cả single/bulk enrollment.
- Mở rộng Scorebook score entry, bulk score, score-change request/filter và các response score/change để nhận hoặc hiển thị `studentCode` và `studentName`.
- Bổ sung endpoint attendance theo student code cho giáo viên và academic office; response exception có thêm mã và tên học sinh.
- Cập nhật completeness evaluation để nội dung thiếu điểm hiển thị `studentCode (studentName)`, có fallback rõ ràng khi hồ sơ không tồn tại.
- Không thay đổi schema database; các API nhận `studentId` cũ vẫn được giữ nguyên.

## 3. Quyết định và giới hạn

- Resolve cả `studentId` và `studentCode` yêu cầu hai giá trị trỏ tới cùng một học sinh; mismatch trả `400 Bad Request`.
- Bulk resolve loại bỏ bản ghi trùng sau khi lookup; Enrollment và bulk score kiểm tra duplicate trước khi bắt đầu mutation.
- Bổ sung alias path attendance theo plan nhưng giữ lại path cũ để không phá client hiện tại.
- Không triển khai frontend, Postman hoặc thay đổi khóa ngoại/schema; các module vẫn lưu quan hệ theo `student_id`.
