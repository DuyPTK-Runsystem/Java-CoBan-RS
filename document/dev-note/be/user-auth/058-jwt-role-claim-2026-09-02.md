  - Documents the new JWT role contract and its non-authoritative FE usage.

## 4. Implementation decisions

- The claim name is `role`, as approved in Plan 058.
- The value is `string[]`, because a user can have multiple roles.
- Role codes are sorted and do not contain the Spring Security `ROLE_` prefix.
- `JwtAuthenticationFilter` was not changed; it still reloads the user and authorities from the database.
- The integration fixture creates `STUDENT` when the H2 test context has no seeded role.
