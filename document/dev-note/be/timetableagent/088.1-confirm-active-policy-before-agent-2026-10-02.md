# Dev Note 088.1 — Confirm active teacher-load policy before agent proposals

**Related plan:** [Developer Plan 088](../../../dev-impl-plan/summary/088-spring-ai-timetable-agent-2026-10-01.md), approved; this scope was approved by the user on 2026-10-02.

## Scope implemented

- Added ADMIN/ACADEMIC_OFFICE `PUT /api/v3/timetables/{id}/teacher-load-policy` with required `policyId` and `expectedVersion`. It locks and accepts only a DRAFT, rejects stale versions and any policy other than the canonical current ACTIVE policy, clears validation summary when the binding changes, flushes the revision, writes a `CONFIRM_TEACHER_LOAD_POLICY` audit row, and returns timetable detail.
- Added `GET /api/v3/teacher-load-policies/active` using the same effective-date-descending repository selection as the agent snapshot guard.
- The agent workspace shows the current policy and requires explicit confirmation for an unbound/stale draft. Proposal generation remains disabled until policy ID and version match. Confirmation and generation refresh the canonical policy; generation is serialized and checks the request/revision binding after the asynchronous refresh.
- Existing `createDraft` optional policy behavior and the snapshot policy guard are unchanged. No migration was needed.
