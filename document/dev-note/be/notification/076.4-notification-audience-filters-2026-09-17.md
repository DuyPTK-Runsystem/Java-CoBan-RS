## 2. Phạm vi đã triển khai

- Extended `GET /api/v3/notifications/audiences/individuals` with server-side `roleCode`, `studentClassId`, `teacherClassId`, `q`, `page`, and `size` filters.
- `studentClassId` matches active enrollment in an active academic year.
- `teacherClassId` matches the union of active homeroom and subject-teaching assignments on active classes in an active academic year.
- Search covers student/teacher name and code plus username; pagination remains a distinct user projection with follow-up context projections.
- Response now includes canonical role codes, the active student-class context, and deduplicated active teacher-class contexts.
- Existing manager role guard, `DEFAULT_SCHOOL` single-school behavior, create/publish eligibility checks, canonical payload, snapshot, and idempotency flow were not changed.

## 4. Decisions, assumptions, and privacy boundary

- Role input is restricted to `STUDENT`, `TEACHER`, `ACADEMIC_OFFICE`, or `ADMIN`.
- Teacher assignment validity follows the existing project convention for active assignment lookup: `AssignmentStatus.ACTIVE`; class/year context is restricted to active class and academic year.
- No credentials, password fields, assignment history, contact data, or raw entities are returned.
- No migration was added; the implementation uses existing tables and read-only projections.
