## 2. Phạm vi đã triển khai

- Added manager-only, fixed `DEFAULT_SCHOOL` scope lookup endpoints:
  - `GET /api/v3/notifications/audiences/classes?q&page&size`
  - `GET /api/v3/notifications/audiences/individuals?q&page&size`
- Added zero-based `ResultPaginationDTO` projections with backend search and bounded page size.
- Added canonical audience guards:
  - `CLASS`: active class, active academic year, active enrollment/student and existing linked user; empty eligible roster is rejected.
  - `INDIVIDUAL`: positive IDs are deduplicated/sorted; user existence and student-link eligibility are re-checked.
- Kept stored legacy individual `targetReference` parsing for publish compatibility, while new requests reject `targetReference` for `INDIVIDUAL`.
- Canonicalized class reference and individual recipient serialization before persistence/fingerprint; receipt uniqueness and publish snapshot flow remain in the existing lifecycle.

## 4. Decisions và migration

- A01–A06 applied as recorded in the Developer Plan. `User` has no status column in current code, so existing `app_user` rows are treated as active; linked students must be `ACTIVE`, and unlinked staff users remain selectable.
- `CLASS` lookup excludes classes with no eligible recipient. Missing class keeps existing `404`; existing-but-stale/ineligible/empty class is rejected as `422`.
- No FE files were changed by this agent.
- No Flyway migration was added: current tables and indexes support the read-only projections; query performance still needs the separate validation/runtime checkpoint.
